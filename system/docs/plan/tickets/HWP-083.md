# Play the first level only, roll back the room chain of HWP-046

The demo plays one level, the forest glade. HWP-046 chained the rooms through an order table so the glade's beacon handed the run over to the ruin gate; that chain is rolled back. The glade's beacon ends the run again, as every beacon did before HWP-046, and the ruin gate stays in the repository as a room played on its own with `?room=ruin-gate`, where HW-002 remains planted and fixable.

## Work

- Delete `game/content/order.ts`, `WorldState.level`, `LevelRoom`, `nextLevelRoom` and `enterNextRoom`; `lightBeacon` in `game/sim/props.ts` holds `victory` for every beacon and no `room:next` event exists anywhere.
- `game/main.ts` boots the default room alone: no level, one stage, no hand-over branch; the `?room=` parameter keeps working. `createScene` takes one room again and the room layer, the props view and the card lose the per-hand-over clearing they only needed for the chain (keep whatever is still needed for a restart).
- Delete `tests/sim/transition.test.ts`, `tests/sim/transition-last-beacon.test.ts` and `tests/smoke/transition.spec.ts`; `tests/sim/forest-scripts.ts` keeps the recorded routes for `forest-room.test.ts`; `tests/smoke/props.spec.ts` may open `/` again.
- Update `docs/plan/02-design/level-design.md` and `simulation-architecture.md`: the demo plays the first beat only, each room ends at its own beacon, and the order module is gone; record that the chain was built in HWP-046 and rolled back here so the pages agree with the code.

## Acceptance

Booting `/` plays the glade and touching its beacon sets `victory`, stops the run clock and shows the banner; `?room=ruin-gate` plays the ruin gate alone with its creature in the log and HW-002 planted; `grep -r "room:next" game tests` finds nothing; `forest-room.test.ts` passes per room; `pnpm bugs:check` still lists HW-001 and HW-002; the gates are green.
