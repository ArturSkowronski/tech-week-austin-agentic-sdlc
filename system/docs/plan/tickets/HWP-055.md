# Plant HW-002, respawn lands one tile left of the flag

## Work

`checkpoint.ts` converts the flag's tile to the respawn position with an off-by-one in the tile-to-world conversion that reads as a plausible mistake. Manifest entry: room `ruin-gate`, hides in the `log`, steps "Raise the flag past the gate, fall into the pit", expected "The wizard respawns at the flag", logs about checkpoint conversion. Paired test: respawn position equals the flag's.

## Acceptance

As HWP-054. The defect applies while the creature is carried: `tick` passes `carried` to the conversion as it does to `mapInput`, and because the respawn position is computed before the death drops the creature, a carried death respawns one tile left of the flag. The main suite's respawn test in `world.test.ts` runs a world without the creature and asserts only that the checkpoint, not the spawn, is used; it must still pass. Document the order in the module comment.
